  URL 编码问题修复说明

【问题分析】

从日志中看到的问题：

Serving photo: D:\car-repair-system\photos\%E7%B2%A4B12345_1770084971857.jpg
Error: ENOENT: no such file or directory, open 'D:\car-repair-system\photos\%E7%B2%A4B12345_1770084971857.jpg'

问题根源：

1. 中文文件名被 URL 编码
   • "粤" 被编码为 %E7%B2%A4
   • 浏览器发送的 URL 是：/photos/%E7%B2%A4B12345_1770084971857.jpg

2. 服务器没有解码就直接使用
   • 服务器直接使用了编码后的路径
   • 导致查找的文件名是 %E7%B2%A4B12345... 而不是 粤B12345...
   • 文件系统中没有这个编码的文件名

3. 找不到文件
   • 实际文件名：粤B12345_1770084971857.jpg
   • 查找的文件名：%E7%B2%A4B12345_1770084971857.jpg
   • 结果：ENOENT (no such file or directory)

═════════════════════════════════════════════════════════════════
【解决方案】

✅ 添加 URL 解码

修复代码：
  • 修改前：filePath = path.join(__dirname, 'photos', req.url.substring(8));
  • 修改后：const photoPath = decodeURIComponent(req.url.substring(8));
            filePath = path.join(__dirname, 'photos', photoPath);

工作原理：
  • decodeURIComponent() 会将 URL 编码解码为原始字符串
  • %E7%B2%A4B12345 → 粤B12345
  • 这样就能找到实际存在的文件了

🔍 URL 编码知识
═════════════════════════════════════════════════════════════════

什么是 URL 编码？

URL 中只能包含 ASCII 字符（a-z, A-Z, 0-9 等）
非 ASCII 字符（如中文）需要编码才能在 URL 中传输

常见的 URL 编码示例：

  • 粤 → %E7%B2%A4
  • B  → B (无需编码）
  • 1  → 1 (无需编码）
  • _  → _ (无需编码）

完整示例：
  /photos/粤B12345.jpg → /photos/%E7%B2%A4B12345.jpg

解码过程：

  • URL: /photos/%E7%B2%A4B12345.jpg
  • 解码: /photos/粤B12345.jpg

💡 关于中文文件名的建议
═════════════════════════════════════════════════════════════════

虽然现在已经修复了 URL 编码问题，但考虑到：

1. 不同的系统和浏览器对中文文件名的处理可能不同
2. 中文文件名在某些情况下可能会出现兼容性问题

建议：

如果需要更好的兼容性，可以考虑：
  • 使用英文或数字作为文件名
  • 或者在代码中自动生成唯一的文件名

但目前的解决方案已经能够正确处理中文文件名了。
